What is it for?

Developers keep their content in Git — but editing raw Markdown files, uploading images somewhere else and wiring their paths by hand is tedious. MDVault manages the whole content bundle: the Markdown, its frontmatter, and every image it references — committed side by side in the same repository.

For blogs & docs

Write long-form articles with headings, tables, code blocks and images, then publish when ready.

For social posts

Draft short, plain-text posts (LinkedIn style) and link them to the article they promote.

For anything else

Define your own content types — notes, tutorials, projects — and MDVault builds the whole workspace around them.

How it works

From your keyboard to your website — your text and your images travel together, through one repository you own.

  1. Point it at a repository

    Provide a GitHub token, owner and repo name. MDVault reads and writes content through the GitHub API — there is no other data store.

  2. Write and upload in the browser

    Content is edited as rich text and serialized to Markdown with YAML frontmatter. Images dropped into the editor are uploaded to the repository's media folder and linked by relative path — optimized on the way in.

  3. Every action is a commit

    Saving, publishing or deleting commits the file with a descriptive message. Conflicts are detected through file SHAs, so concurrent edits can't silently overwrite each other.

  4. Your site consumes the repo

    Your static site, blog or app reads the same Markdown files and the same image files straight from Git — MDVault never sits between your content and your build.

Getting started

1. Prepare a repository & token

Create (or pick) a GitHub repository for your content, then generate a fine-grained personal access token limited to it with Contents: read and write and Metadata: read-only.

2. Run with Docker

services:
  mdvault:
    image: ghcr.io/victor3spoir/mdvault:latest
    ports:
      - "127.0.0.1:3000:3000"
    environment:
      GITHUB_TOKEN: "your_personal_access_token"
      GITHUB_OWNER: "your_github_username"
      GITHUB_REPO: "your_content_repository"
    restart: unless-stopped
docker compose up -d

3. Open the app

Visit http://127.0.0.1:3000, then head to Settings → Dynamic Content to define your own asset types, or start writing straight away.

Configuration

Variable Description Default
GITHUB_TOKEN Token used to read and write repository content Required
GITHUB_OWNER User or organization owning the repository Required
GITHUB_REPO Content repository name Required
ARTICLES_PATH Directory containing articles articles
POSTS_PATH Directory containing posts posts
MEDIA_PATH Directory containing media files media
Security model. MDVault has no application login by design — the GitHub token authenticates the app to GitHub, not people to the app. Run it on a trusted network or behind a VPN, firewall or authenticating reverse proxy. Do not expose it directly to the public internet.
